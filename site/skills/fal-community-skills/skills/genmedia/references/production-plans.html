Terminal production plans

Read the genmedia skill for terminal execution, or fal-media for connected MCP execution. Read only the named production references needed by this brief. Use current published routing or discover a candidate. Verify exact endpoints, input schemas, output shape and price units before constructing inputs. Preserve an explicitly named model. Candidate IDs below were schema-checked on 2026-11-05; availability and price can change.

For terminal agents, copy the invoking skill's assets/plan.json into the project. Replace every REPLACE_ value with the actual prompt, URL or locale. Inspect each stage's live schema and price, then run the shared helper from the installed genmedia skill (locate its installation path; do not assume the current directory):

python3 /path/to/genmedia/scripts/run_plan.py plan.json --stage hero
python3 /path/to/genmedia/scripts/run_plan.py plan.json --stage hero --execute --state ./production-state
python3 /path/to/genmedia/scripts/run_plan.py plan.json --stage hero --poll --state ./production-state

The first command prints a dry run. Use the actual stage ID from the plan. --execute spends on that stage only. The helper records schema, pricing and the submission response. It refuses a second submission for the same stage. --poll checks the saved request and downloads its output. A failed or uncertain submit needs manual reconciliation, not a blind retry. Copy verified output URLs into later stage inputs after visual review. Never use a local path where a URL is required.

Keep a project manifest with source assets, endpoint, inputs, request ID, output URL, local file, dimensions/duration, cost estimate, and QA findings for every stage. Produce only the requested variants within the existing budget. Return observed failures and missing capabilities; do not substitute a plan for a requested artifact.
